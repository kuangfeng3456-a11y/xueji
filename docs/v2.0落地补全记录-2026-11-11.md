## 八、事件总线与总教练路由（7.5）

`services/event_bus.py` 把「发生了什么」转成「该调用谁」：

## 十四、出题质量修复：英语科目不再出中文题 / 元问题

现象：听力知识点生成的随堂测出现中文题干「在短对话中，以下哪项最符合“言外之意”的理解方式？」，
这不是学科题，而是关于学习方法的元问题。原因是出题提示词只给了知识点名称，没有学科与语言约束。

修复（`backend/app/services/item_policy.py` + `quiz.py` / `probes.py`）：

- **学科策略**：考试名含英语/四级/六级/CET/雅思/托福时，题干与选项必须是英文（解析可中文）；
  听力要求给出真实对话或独白片段，阅读要给英文句子/段落，词汇考具体词义或搭配；
- **元问题拦截**：`属于哪个模块 / 最需要先确认 / 最符合…理解方式 / 学习策略 / 复习方法` 等模式直接丢弃；
- **重试一次**：首次输出不合格时，追加「上次不合格，按 subject_policy 重写」再请求一次；
- **如实兜底**：两次都不合格则回退规则题，并在响应里保留 `engine=rule`，前端标注「规则兜底」；
- 英语科目若模型不可用，规则题会明确是知识点核对题，不再伪装成真题练习。

实测（真实 DeepSeek）：

```
W: I thought you were going to the concert with us tonight.
M: I was, but my sister asked me to help her move into her new apartment.
What will the man probably do tonight?
A. Help his sister move  B. Go to the concert  C. Visit his sister's old apartment  D. Stay at home alone
```

## 二十四、反向教学三件套移植（2026-11-12）

来源：旧项目 `C:/Users/HP/WorkBuddy/2026-10-31-17-46-50/xueji` 的 `skills/feynman.py`、`reverse_grader.py`、`immune.py`。该项目的核心不是「多一个 AI 功能」，而是一套**判定不经过模型**的防守设计：判定基准在服务端预置，模型只负责出题面与辅助判分，因此结果可复现、可解释、可测试。这三件套按当前项目的模型与规则重写后并入。

### 1. 共同设计原则
| 原则 | 具体做法 |
|---|---|
| 基准预置、不下发 | 费曼的讲解要点、判卷的错步/错因/修正关键词、免疫的诱饵键与正确键，全部在**开始**时写进数据库，响应体里不含这些字段 |
| 判定确定性 | 覆盖率 = 命中要点数 / 总要点数；判卷 = 45 定位 + 30 错因 + 25 修正；免疫 = 键比对。模型挂掉时退回 `graph`/`rule`/`replay`，分数不变 |
| engine 如实标注 | 每个产物都带 `llm / graph / rule / replay / mixed`，前端直接显示「引擎 llm」，不假装全是 AI |
| 结果落回掌握度 | 判完之后统一走 `apply_answer()`，与做题共用一套掌握度与复习间隔，不是孤立的演示模块 |

### 2. 费曼检验场（`feynman-check`）
- 挑题：`_pick_feynman_kp()` 只挑「掌握度 ≥ 0.5 且做错过题」的知识点——正是「以为会了」的高危区；同知识点 6 次内轮换降权，避免反复轰炸同一个。
- 要点：4~6 条 `term + hint`。`llm → graph → rule` 三级降级：模型给不出就取知识点的子节点名做要点，再不行用通用五问（定义 / 前提条件 / 用法 / 易错点 / 与其他知识的联系）。
- 判分：讲解文本做标点与符号归一（`≠ ≥ ≤ → ± ∞` 等），逐要点判定「讲没讲到」，`coverage = covered / total`。另有 `suspects`——同一段话里同时出现某要点词与否定词的，标为「疑似提到」，只提示不计分。
- 产出：`insight` 文案按覆盖率分档；`feynman_profile` 生成**熟练度错觉榜**，`gap = 掌握度 − 平均覆盖率`，差距越大越危险（如「非谓语动词 自测 51% / 讲出 0%，差 51pt」）。
- 讲解少于 30 字直接 400（「讲解太短了，说不清就是没学会」），同一 session 不能重复提交。

### 3. 反向判卷（`reverse-grader`）
- AI 扮演一个犯错学生交卷：`steps` 至少 3 步，出题时同时写死 `error_step`（错在第几步）、`error_type`（概念不清 / 方法不会 / 粗心）、`correct_step`（正确写法）、`key_terms`（修正必须提到的词）。
- 学生（用户）要做三件事，各对应一段分数：
  - 定位 `45`：命中 `error_step` 得满分；只相邻一步得 `15`（「差一步」）；完全偏了 0。
  - 错因 `30`：三类里选对才给。
  - 修正 `25`：`_judge_fix()` 判 `key_terms` 覆盖，按比例给分。
- `verdict` 按三段分数的组合分 7 档，保证结论与分数不矛盾（例：45 分 = 定位准 + 错因错 + 修正空 → 「位置找对了，但错因说错：你知道这里不对，却说不清为什么不对」）。
- `reverse_profile` 做交叉洞察：把「用户自己做题时的错因分布」与「判卷时能发现哪类错因」对照——常犯「概念不清」却只发现 0/2，说明对这类错误缺辨别力。
- 错因按已完成次数轮换，避免每次都是同一类。

### 4. 错误免疫（`error-immunity`）
- 立项门槛：指纹 = `错因 × 板块`，同类错误出现 **≥ 2 次**才立项，杜绝单次失误被当成病灶。当前库里有 5 个指纹（概念不清·听力 7 次、概念不清·高等数学 7 次、概念不清·阅读 5 次、方法不会·听力 3 次、方法不会·高等数学 2 次）。
- 出题：优先 `replay`——直接把用户当初答错的原题重演，`trap_key` 放当初他选的那个错项，`correct_key` 放正确项，键值写死，前端只拿到打乱后的 4 个选项文本。
- 判定：选中 `trap_key` = `relapse`（中招）；选中 `correct_key` = `guard`（守住）；选其他 = `miss`（抗体偏弱，不算复发）。
- 免疫达成：连续守住 **3** 次 → `immune`；14 天不练开始衰减。`immune_profile` 给出指纹数 / 已免疫 / 复发预警 / 守住率。

| 晚上 | 19:00-22:00 | review 复盘 | 回看错题、按记忆稳定度排明天的复习 |

### 4. 关键坑与修法（都是实测出来的）
- **考点天天重复**：原来按掌握度打分排序，掌握度差异（可达 2.0）压过轮转顺序，导致连续多天排同一批考点。改为 `role == "new"` 走**课程序列推进**——按重要度排 `curriculum`，第 N 天取窗口 `(day_index-1) * day_window % size` 起的一段，`day_window = max(4, size//2)`，天然形成间隔复习。实测第 5/6/7/8 天考点全部错开。
- **阶段考试日排不出知识点**：`used` 计数器原本全局限制同一知识点最多出现 2 次（16 点 × 2 = 32 < 需要的 320 槽位）。改为 `used_today` 每天重置，跨天允许重复（重复本身就是复习）。
- **CET-4 目标混进数学知识点**：演示库目标 1 里塞了全部学科包。新增 `_relevant_points()`，按 `item_policy.exam_is_english` + 理科/英语关键词表过滤，修完第一天全是英语考点。
- **三个时段返回同一批视频**：`search_videos` 原来按顺序去重合并，第一个关键词就占满。改为**按关键词分桶 + 轮转合并**；`_attach_videos` 改为「学科前缀 + 知识点」精确词优先，父模块兜底词只在精确词失败时启用。
- **英语知识点搜不到课**：实测「句子结构」0 结果、「英语 句子结构」3 结果。`_search_prefix()` 对英语类统一冠「英语」。
- **阶段模考只考前 3 个考点**：12 个考点出 6 题，模型会自己挑 3 个点各出 2 题。修复三处：`kp_ids` 场景按 `mastery_map` 升序取最薄弱 `count` 个考点、`per_point = 1`、缓存取题加 `taken` 计数保证每个点只取 1 题。实测覆盖 6 个不同考点。
- **`per_point` 改动打破既有语义**：一度让 `_llm_questions` 在多知识点时默认走逐点调用，导致 `test_quiz.py::test_llm_questions_accepts_valid_payload`（断言单次调用）失败。改为**显式 `per_point` 参数**，只在阶段考试（`kp_ids` 非空）时传 `True`。

### 5. 接口（`api/exam_prep.py`，prefix `/goals`）
| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/{goal_id}/exam-prep` | 整套方案，无则实时生成并落库 |
| POST | `/{goal_id}/exam-prep/build` | 重建（`regenerate: true`），先删后建不留重复 |
| GET | `/{goal_id}/exam-prep/day/{day_index}` | 某天三段课表 + 知识网络 + 视频（**只在打开某天时联网**，生成方案时不批量拉取） |
| POST | `/{goal_id}/exam-prep/stage-exam` | 阶段模考出卷（`stage_id`、`count` 2~12） |
| POST | `/{goal_id}/exam-prep/stage-exam/submit` | 判分并写回阶段（≥60% 为通过） |

新增两张表：`ExamPrepStage`（阶段 + 模考成绩）、`ExamPrepDay`（每日三段课表 JSON，`unique(user_id, goal_id, day_index)`）。**后端新增模型与路由，必须重启后端才生效。**

### 6. 前端（`views/ExamPrep.vue`）
阶段时间轴（比例、目标保持率、模考成绩）→ 天数 chip 选择器（14 天，带模考旗标）→ 三段时段卡（知识点 + 掌握度、知识网络节点与先修/易混淆边、真实视频卡、随堂测入口）→ 试卷与判分区。响应式：≤1100px 阶段两列 + 时段单列，≤640px 阶段单列 + 视频竖排。

### 7. 封面 403：B 站图床防盗链
验收时发现 9 张封面 `naturalWidth` 全是 0。逐步排查：图片直链在浏览器单独打开正常（1440px）、curl 无 Referer 返回 200、带 `Referer: http://127.0.0.1:8010/` 返回 **403**；页面内 `fetch` 拿到 `403 text/html`，网络面板显示 `net::ERR_BLOCKED_BY_ORB`（拿到 HTML 错误页被浏览器按 ORB 拦掉）。

结论：**任何非 bilibili 域名引用该图床都会被拒**，本地和线上部署都一样，前端加 `referrerpolicy` 只能绕过一部分场景，不可靠。

修法：新增 `api/media_proxy.py`，`GET /api/media/image?url=...` 服务端带 `Referer: https://www.bilibili.com/` 取图后转发。安全上做三件事：域名白名单（仅 `i0/i1/i2.hdslb.com`、`archive.biliimg.com`）、只允许 http/https、响应必须是图片 MIME（拿到 HTML 直接 415）。`video_search` 返回值新增 `cover_proxy`，前端 `coverOf()` 优先走代理，失败时 `@error` 回落到原图并隐藏占位。实测代理返回 `image/jpeg` 176855 字节，白名单外域名返回 400，验收 **9/9 封面加载**。

### 8. 顺手修掉的两个前端 bug
- **掌握度全显示 0%**：`slot.mastery` 是 `{"10": 0.61}` 这种以 kp_id 字符串为键的字典，模板却用 `kp_names.indexOf(kp)`（下标）去取值，永远 undefined。新增 `masteryOf(slot, index)`，用 `slot.kp_ids[index]` 查。修完上午三个点显示 61% / 58% / 98%，与知识网络一致。
- **晚间只显示 2 个知识点却说 3 个**：`v-for` 的 `:key="kp"` 用了知识点名，复盘时段重复出现同一知识点时 key 冲突被 Vue 丢弃节点。改为 `` `${kp}-${index}` ``。

## 二十八、阅读与听力改为真实题型：文章题与音频题（2026-11-14）

用户拿着两张截图反馈：选了「阅读」出的是「What is the main idea of the passage?」但**根本没有文章**；选了「听力」出的是「W: … M: …」把对话原文**印在题干里**，等于让人读文本。这两类都不是真题型。

### 1. 根因
- 出题链路只有「一句话题干 + 四个选项」这一种结构，阅读/听力全靠模型自己在题干里塞文章或对话；题干长度一超就被截断，看起来像题、实际无从作答。
- 听力尤其错位：原文直接印在卷面上，考的是阅读而不是听力。

### 2. 设计：材料型题目（`services/quiz_material.py`）
引入「材料 + 多题」结构，一次出题的若干小题共享同一份材料：

| 题型 | 材料 | 前端 |
|---|---|---|
| 阅读 passage | 180-260 词完整英文文章（3-4 段） | 文章卡片，可折叠，标注词数 |
| 听力 listening | 80-180 词对话/短文脚本 | **只给播放器**，交卷后才开放原文 |

判定由知识点名决定（`material_kind`）：命中 `听力/短对话/长对话/听力篇章` → listening；命中 `阅读/仔细阅读/长篇阅读/选词填空` → passage；数学类一律不出材料题。听力与阅读混选时按数量多的一类走，避免一次随堂测混两种材料。

### 3. 关键实现点
- **token 预算**：`llm.chat_json` 默认 `max_tokens=900`，一篇文章加 3 题必被截断，JSON 解析失败 → 材料题永远回落普通题。材料题单独放宽到 3200（听力 2600），失败再重试一次。这是本次最隐蔽的一个坑。
- **题量补齐**：模型常只出 2 题。先在同一份材料下续出（把材料原文贴回提示词，禁止换话题），仍不够则追加第二份材料（真实听力本来就是一个 section 多段）。每份材料有自己的 `id`。
- **答案打散**：模型倾向把正确答案放 A，实测「全选 A」能拿 100 分。`_shuffle_options` 以材料 id 为种子同步置换选项、`option_reasons`、`distractor_causes`，判分口径不变且结果可复现。修完全选 A 得 0 分。
- **听力原文不给卷面**：出卷时 `public_material` 只返回 `audio_script`（供前端 TTS 朗读），不返回可读段落；`transcript` 只在交卷后的 `materials` 里出现。
- **接口序列化**：`QuizQuestionOut` / `QuizResultOut` 是 response_model 白名单，新增的 `material` / `materials` 字段不加就**会被 FastAPI 静默丢弃**——排查时一度以为服务层没生效，实为序列化层截断。

### 4. 前端
新增 `components/QuizMaterial.vue`：
- 阅读：标题 + 词数 + 正文段落，可收起；
- 听力：播放/重听/语速 0.8x·1x·1.2x（`speechSynthesis`，优先本地英文语音）、「听力原文将在交卷后开放」；不支持语音合成或没装英文语音包时给出明确提示，不静默失败。

`Quiz.vue` 与 `ExamPrep.vue` 的试卷区都改为**按 `material.id` 分组渲染**，材料在组首渲染一次；判分结果区新增「本次材料（可展开原文复盘）」。

### 5. 验收
| 项 | 结果 |
|---|---|
| 阅读（kp=阅读） | material=passage，220 词，3 题，有正文 |
| 阅读（kp=长篇阅读） | material=passage，226 词，4 题 |
| 听力（kp=听力） | material=listening，120 词，3 题，**无 content 字段** |
| 听力（kp=短对话） | material=listening，168 词，4 题 |
| 写作（kp=议论文结构） | 普通题（写作不需要材料，符合预期） |
| 全选 A | 修复前 100 分 → 修复后 0 分 |
| 交卷后 | `materials` 返回 1 条，听力 `transcript` 可见 |
| 浏览器 1500×1400 | 听力块 1、播放按钮正常、可读原文块 0、锁定提示正确、题干 3；阅读块 1、段落 4、220 词、题干 3；交卷后「查看听力原文」可展开，`exceptions: []` |

回归：`test_quiz_material.py` 新增 8 例全通过；连同 `test_quiz / test_quiz_distractor_cause / test_exam_prep / test_probes / test_question_bank / test_api_core` 共 **155 passed**。同步更新了 `test_quiz.py` 里对判分返回全等比较的断言（新增 `materials` 字段）。

### 6. 已知边界
- 听力音频依赖浏览器语音合成，音色取决于系统语音包；离线且无英文语音时会提示「无英文语音包」，可降级看原文作答。
- 阶段模考（`kp_ids` 多考点）仍走普通题：一次覆盖 6 个考点混多份材料会让卷面结构混乱，暂不做；随堂测已完全支持。
- 阅读材料仍是模型生成而非真题库原文，标注为「模型生成（非真题库）」，不冒充真题。

## 二十九、按知识点配置题库：题与考点一一对应（2026-11-14）

### 1. 问题
随堂测的考点下拉里，用户选了「定积分」却看到「仔细阅读」的题、选了「阅读」却把整篇文章的题挂到「选词填空」名下——题目和考点对不上。根因有三层：

1. **没有真正的题库**：题目全靠模型现编，每题都标「模型生成（非真题库）」，无法按考点稳定取题；
2. **父模块被拆成子模块出题**：选「阅读」（父）时按子知识点 `仔细阅读 / 选词填空 / 长篇阅读` 出题，题卡标签自然对不上；
3. **内置题库每知识点只有 4 题**：连着做两次就重复，题库名存实亡。

### 2. 做法

**（1）部署 tikuAdapter 作为题库服务**

`external/tikuAdapter`（`v0.1.0-beta.41` Windows 二进制，前端已 embed，端口固定 8060），与「学迹」后端 8000 并行运行。选它是因为带 Web 管理后台：题库可增删改查、可导入 Word、有操作日志，老师改题不用改代码。

**（2）课程名 = 知识点名**

tikuAdapter 的 `course_name` 是唯一能精确筛选的字段，于是约定「一个知识点 = 题库里的一门课」：

```
course_name = 定积分        # 这门课下的题只会出给「定积分」
question    = 题干
options     = JSON 数组
answer      = JSON 数组（答案文本）
extra       = 解析
```

`scripts/seed_tiku_adapter.py` 按库里所有目标的知识点逐点灌库，幂等（先读已有题干再跳过）。当前灌入 **16 个数学考点 / 199 题**。

**（3）程序化补题，答案由公式算出**

新增 `services/qbank_generated.py`：定积分、导数与微分、函数与极限、线性代数（行列式/矩阵/向量/特征值）、级数、概率论各知识点用参数化题目补齐，答案用 `Fraction` 精确计算，不靠手写记忆。合并进内置题库时按**全局题干去重**，同一道题不会跨两个库出现（否则「矩阵」的测验会抽到「行列式」的题）。补完后每点 10–18 题。

**（4）出题优先级改为「题库优先」**

```
自建题库（按考点取题）→ 通用外部题库 API → 模型生成 → 内置题库 → 规则题
```

`fetch_online_bank()` 新增题库这一层；`engine` 新增 `tiku` / `tiku+bank` / `tiku+llm` 标签，前端显示「题库出题（按考点取题）」。

**（5）父模块自带题库时按父模块出题**

`generate_quiz()` 里，若所选知识点有子节点、且父节点自身有题库（`阅读 / 听力 / 高等数学 / 线性代数`），直接以父节点出题。这一步同时修好了两件事：题卡标签回到用户所选的考点；阅读/听力能拿到父节点的 `material_kind` 判定，继续走材料题。

**（6）考点下拉显示来源**

`GET /goals/{id}/question-banks` 新增 `tiku_question_count`、`all_points`（含父模块）、`tiku_adapter` 状态。下拉每项右侧显示「16 题 / 阅读文章 / 听力材料」，选考点前就知道这个点从哪出题。

### 3. 验收
| 考点 | 题源 | 题目 | 标签 |
|---|---|---|---|
| 阅读 | 材料题（模型生成文章） | 182 词文章 + 3 题 | `阅读`（原来错成 `仔细阅读/选词填空`） |
| 听力 | 材料题（模型生成脚本） | 听力脚本 + 3 题，无正文 | `听力` |
| 高等数学 | 题库 | 连续/极限/定义域 | `高等数学` |
| 函数与极限 | 题库 18 题 | 间断点类型、重要极限 | `函数与极限` |
| 定积分 | 题库 16 题 | ∫₁^e 1/x dx、∫₀^(π/2) cos x | `定积分` |
| 导数与微分 | 题库 15 题 | 单调区间、极值必要条件、微分 | `导数与微分` |
| 线性代数 | 题库 12 题 | 可逆充要条件、维度规则、\|2A\| | `线性代数` |

浏览器实测：下拉显示 `定积分（9%）｜16 题`、`阅读（8%）｜阅读文章`、`听力（0%）｜听力材料`；选中定积分出题后，3 道题全部标注「知识点：定积分 · 来源：题库（tikuAdapter）」，答案经手算复核（∫₁^e 1/x = 1、∫₀^(π/2) cos x = 1、∫₀^4 4x = 32）。

测试：新增 `test_tiku_bank.py` 8 例；全量 `pytest tests -q` **883 passed, 1 skipped**。顺带修掉一处随机失败：材料题 id 原本用 `uuid4`，导致「选项打散」每次不同、`test_material_set_...shuffles_options` 约 1/16 概率失败；改为「题型+标题+正文」的 md5，同一份材料必然得到同一个 id 与同一套选项顺序（符合项目「可复算」原则）。

### 4. 已知边界
- 英语阅读/听力**不入题库**：真题形态是「整篇文章 + 多题」，单句式题库撑不起来，继续由模型生成并标注「模型生成（非真题库）」。
- 题库答案由 `选项文本 == 答案文本` 匹配回下标，题库里手改答案时若写成 `B` 而非选项原文会对不上，这类脏数据会被丢弃而不是判错。
- tikuAdapter 与后端同机部署，`TIKU_ADAPTER_URL` 默认为 `http://127.0.0.1:8060`；换机器部署时需同步改 `.env` 并重跑灌库脚本。

## 三十、商用化收敛：模块分级、口令下线、错误兜底（2026-11-14）

### 1. 问题：功能都在跑，但不像一个能卖的产品

用无头浏览器把 34 个标签页逐个打开，控制台与请求**没有任何报错**——所以问题不在「页面坏了」，而在三件商用才会暴露的事：

1. **入口太多**：6 个板块 35 个标签，个人考生要在一堆「班级看板 / 学习搭子 / 心理自评 / 模型评测 / 系统接入」里找今天该做什么；
2. **演示口令写在前端**：`Login.vue` 里直接写着 `demo / 密码`，还带「一键填入」按钮，且填的密码与 `seed.py` 里的对不上（点了一键填入反而登不进去）；
3. **出错没兜底**：`fetch` 没有超时，网络挂起时页面永远转圈；未捕获的 Promise rejection 用户毫无感知；`confirm()` 原生弹窗阻塞主线程、手机上样式不可控。

### 2. 做法

**（1）模块按受众分级，而不是删页面**

`sections.js` 给每个标签加 `audience`：`core`（个人备考主流程）/ `campus`（校园 B 端）/ `internal`（运营研发）。侧边栏与页内标签只渲染前两类，`internal` 只保留深链：

```
今日 5 ｜ 计划 5 ｜ 练习与复盘 5 ｜ 诊断与决策 9 ｜ 校园协作 3   → 27 个开放模块
内部：未来模拟、策略实验、学习搭子、心理自评、恢复站、模型评测、能力 Skills、系统接入
```

收起的都是**商用 v1 不该承诺的东西**：学习搭子需要社交审核、心理自评（PHQ-9/GAD-7）属于临床量表、恢复站依赖第三方内容源且涉版权、模型评测与系统接入是运维工具。代码一行没删，改 `audience` 即可恢复。

顺带修掉三处「可见页面指向隐藏页」的死路：驾驶舱的快捷卡改为数字孪生 / 评审团，学情洞察与风险救援去掉「去做策略实验」链接，用户菜单去掉「查看能力 Skills」。

****（2）补上「设置 → 账号与安全」**

原来的 34 个页面里根本没有设置页：改昵称、改密码、导出数据、注销账号散落在「目标与资料」和用户菜单，商用产品缺这一块会直接被用户问「密码怎么改」。新增：

| 层 | 内容 |
|---|---|
| 后端 | `PATCH /api/auth/me`（昵称/学校，昵称非空校验）、`POST /api/auth/me/password`（校验原密码、拒绝与原密码相同、6 位下限） |
| 前端 | `views/AccountSettings.vue`：账号信息、展示资料、改密码（两次输入一致性在前端先拦）、导出学习数据、注销账号（走确认弹窗） |
| 信息架构 | 06 设置板块恢复可见，`账号与安全` 为 `core`，运维三项仍为 `internal` |

顺带把「目标与资料」里重复的导出/删除按钮收成一句「去账号与安全」，同一件事只留一个入口。

**（3）口令从前端下线，改由服务端按需下发**

- `settings.DEMO_HINT`（env `DEMO_HINT`）默认为空；`/api/meta` 带出该字段，登录页**只有拿到非空值才渲染演示账号块**。
- 顺带修掉「一键填入登不进去」：现在从 `DEMO_HINT` 解析 `用户名 / 密码`，不再写死。
- `seed.py` 的 demo 口令改为 `SEED_DEMO_PASSWORD` → 未配置则 `secrets.token_urlsafe(9)` 随机生成并只在输出里打印一次；仓库里不再有可用口令。
- README、STARTUP_GUIDE、审计文档里的明文全部改写成「由 seed 输出」。

**（4）错误兜底**

| 项 | 改法 |
|---|---|
| 请求超时 | `apiFetch` 用 `AbortController`，默认 30s；出题、方案重建、模考、评审团、探针、OCR、上传等长任务单独放宽（`LONG_TIMEOUT` 180s / 上传 60s）。超时提示「请求超时（30 秒）」而不是笼统的「无法连接」 |
| 在途请求 | 统一登记，退出登录时 `cancelPendingRequests()` 全部取消，避免上个账号的数据回写到新会话 |
| 全局错误边界 | `app.config.errorHandler` + `unhandledrejection`：控制台留完整堆栈，界面只给一句「可刷新重试」，不把 Error 对象糊到用户脸上 |
| 陈旧数据 | 首页刷新失败不再静默保留旧数据，顶部出现「这页数据可能不是最新：<原因> · 重试」 |

**（5）确认弹窗替换原生 `confirm()`**

新增 `confirm.js` + `ConfirmDialog.vue`，Promise 化调用，9 处原生调用全部替换。危险操作默认聚焦「取消」（避免回车误删），支持 ESC 关闭、Tab 在两个按钮间循环、移动端按钮竖排。文案也补了「为什么危险」这一行，例如删除班级会写明「成员的个人学习数据保留」。

## 三十一、账号安全补完：自助找回密码与多设备会话（2026-11-14）

第三十节把「忘记密码只能找管理员」「没有多设备管理」列为已知边界。这两条在商用场景里都不是小问题：用户一旦忘记密码就流失，账号被盗后也无法自查。本节把两者补完，前提是**不引入邮件与短信通道**。

### 1. 为什么不做「假发邮件」

没有通道却做「已发送验证码到你的邮箱」，是最常见的伪功能：用户等不到邮件，客服也查不到。所以这里只做两种真正的自我证明方式：

| 方式 | 凭据 | 特点 |
|---|---|---|
| 密保问题 | 用户自选 2 个问题 + 答案 | 注册后可在设置里配置；答案归一化（忽略大小写与空格）后 pbkdf2 哈希存储 |
| 一次性恢复码 | 8 枚 `XJ-XXXX-XXXX` | 生成时明文只返回一次，库里只有 sha256；用过即作废 |

验证通过后签发 10 分钟有效的一次性票据（`password_reset_tickets`），凭票据才能重设密码。票据用过即失效，同一时间只保留一枚。

### 2. 防爆破与防枚举

- **单账号锁定**：连续 5 次验证失败锁定 15 分钟（`recovery_profiles.fail_count / locked_until`），锁定期间即使答案正确也不放行。
- **统一错误文案**：账号不存在与答案错误返回同一句「验证信息不正确」，不通过提示语泄露账号是否存在。
- **IP 限流**：`/recovery/options` 与 `/recovery/verify` 用 `cache.incr` 按 IP 计数。阈值调得较宽（120 次 / 5 分钟），因为校园网络大量学生共用出口 IP，收得太紧会误伤整间机房。
- **答案不可逆**：数据库泄露也拿不到原始答案；恢复码同理。

题面本身必须返回给前端才能作答，这是密保方案的固有取舍，因此靠限流而不是靠隐藏来降低枚举价值。

### 3. 多设备会话

JWT 新增 `jti`，服务端 `auth_sessions` 表一行对应一台设备。`get_current_user` 除了验签与过期，还要确认这枚 token 的会话没有被撤销——这是「退出其他设备」真正生效的关键，而不是只清前端的 localStorage。

| 场景 | 行为 |
|---|---|
| 登录 / 注册 | 开一条会话，记录设备、平台、IP、UA、创建与最后活跃时间 |
| 设置 → 登录设备 | 列出在线设备，标记「当前设备」，可单台下线 |
| 退出其他设备 | 撤销除当前 jti 外的全部会话 |
| 修改密码 | 校验原密码后撤销其他会话，只保留当前设备 |
| 找回密码成功 | 撤销该账号全部会话，所有设备重新登录 |
| 退出登录 | 服务端撤销当前会话（`POST /auth/logout`），再清本地 |
| 删除账号 | 会话、密保、恢复码、票据一并清除 |

设备名由 UA 解析成「浏览器 · 系统」（如 `Safari · iPhone`），平台枚举 `web / ios / android / miniprogram` 供前端显示图标。`last_seen_at` 按 60 秒节流更新，避免每个请求都写库把会话表变成写入热点。过期会话在列表示与登录时顺手清理。

### 4. 无 jti 的历史 token

升级前签发的 token 没有 `jti`，服务端无法判定它是否已被撤销。对这类 token 一律返回 401「登录凭据已升级，请重新登录」——宁可让用户重登一次，也不留下不可撤销的凭据。有效期最长 7 天，影响面有限。

### 5. 管理员兜底

用户既没设密保、也没存恢复码时，运营可在服务器执行：

```bash
python backend/scripts/reset_password.py <用户名>            # 随机密码
python backend/scripts/reset_password.py <用户名> --password <新密码>
```

脚本同时让该账号所有会话下线，新密码只在终端打印一次。

- 新增 `#/recover` 独立找回页（三步：确认账号 → 回答问题/输入恢复码 → 设置新密码），登录页「忘记密码？」直接进入，不再是「暂未开放」的提示。

- 修改密码的说明文案从「其他设备不会自动失效」改为「其他设备会立刻退出」，与真实行为一致。
- `App.vue` 的 toast 移出 `.shell`，登录与找回页的提示现在能正常显示（此前公共页面的错误提示其实看不到）。
