# 7. 文档演进历史与规划分析

## 7.1 三份规划稿的关系与演进

### 7.1.1 定位与阶段

| 文件 | 篇幅 | 定位 | 内容侧重 |
|------|------|------|----------|
| `_plan_doc.txt` | 27.8 KB / 258 行 | **升级建议书** | 以"竞赛增强版"为标题，提出 15 项创新模块建议 + AI 编程提示词模板；明确声明"新模块均为升级设计建议，不代表已实现" |
| `_plan_v1.txt` | 39.8 KB / 462 行 | **完整 PRD V1** | 正式产品需求文档，含 20 章（概述、用户场景、功能架构、算法、数据模型、API、页面、华为云、安全、测试、演示、AI 提示词等）；版本标注"V1.0 · 2026年11月" |
| `_plan_v2.txt` | 150.7 KB / 1953 行 | **项目文档 V2（交付级）** | 在 V1 基础上全面升级，含完整算法公式与算例、19 条提示词全文（P00–P18）、LSV JSON Schema、部署拓扑、答辩 Q&A 预案、评测指标体系；版本标注"v2.0 · 2026年11月" |

**演进关系**：`_plan_doc` → `_plan_v1` → `_plan_v2` 是"建议 → PRD → 交付文档"的三阶段递进。`_plan_doc` 是外部顾问/AI 给出的升级方向建议；`_plan_v1` 将其结构化为正式产品需求；`_plan_v2` 进一步细化为可直接用于竞赛答辩的项目文档，并附带完整的提示词库和算法算例。

### 7.1.2 从 V1 到 V2 的膨胀分析

V2 体积是 V1 的 **3.8 倍**（150.7 KB vs 39.8 KB）。膨胀主要来自以下新增内容：

| 新增内容 | 估算占比 | 性质 |
|----------|----------|------|
| 附录 E：19 条提示词全文（P00–P18） | ~40% | 实质性工程交付物，非冗余 |
| 第五章：核心算法公式与算例（BKT-lite、遗忘曲线、收益密度排程、蒙特卡洛等） | ~15% | V1 仅有原则描述，V2 给出可复算公式 |
| 升级说明（0.1–0.3）：v1.0 现状诊断 + v2.0 创新全景 | ~5% | 增量对照表 |
| 第六章：提示词工程体系（五层结构、自愈环、评测、安全） | ~10% | V1 无此体系 |
| 演示策略与答辩 Q&A（第十章） | ~5% | 竞赛实操内容 |
| 其余章节细化（数据模型扩展、安全合规、测试评估等） | ~25% | V1 框架的深化 |

**判断**：膨胀主要是**真实内容增长**而非 AI 生成堆叠。提示词库和算法算例占了近 55% 的增量，这些是可执行的工程资产。但 V2 也存在一定的重复表述——例如"规则管事实、模型管表达"原则在多处反复出现，升级说明与正文有部分重叠。整体而言，V2 是一份高质量的竞赛交付文档，不是注水产物。

### 7.1.3 V2 相对 V1 的核心新增

- **学习者状态向量（LSV）**：统一数据底座，所有智能体共享同一份带版本号的状态快照（V1 无此概念）
- **BKT-lite 掌握度模型**：替代 V1 的固定系数 0.3 指数平滑，引入猜测/失误/学习参数和置信度
- **自适应遗忘曲线**：记忆稳定度 S 替代固定 1/2/4/7/15 天间隔
- **收益密度排程**：按"价值/分钟"贪心装入，替代 V1 的简单优先级排序
- **任务弹性阶梯**：标准/精简/最小三档，降档优先于删除
- **提示词工程体系**：19 条版本化提示词 + 七层校验自愈环 + 评测集
- **5+1 信息架构**：27 页收敛为 5 个一级入口
- **心理数据隔离与危机转介**：E2 安全合规
- **AI 内容标识**：E3 合规（响应 2025 年 9 月施行的标识办法）

## 7.2 原始需求与目标用户画像

### 痛点定义

三份文档一致定义了四个核心痛点（`_plan_doc` §一、`project_doc.md` §1.1、`func_effect.md` §一）：

1. **有资料没计划**：面对一堆资料不知道每天学什么
2. **计划坚持不下去**：静态计划落后一次就整份作废
3. **错题不复盘**：只记录对错不分析原因
4. **通用 AI 不了解你**：每次重新交代背景

V2 新增第五个痛点：**AI 的建议无法被验证**——给了计划说不清依据。

### 目标用户

明确定义为"有明确考试或认证目标的**大学生**"（四六级、考研、计算机等级、HCIA）。V1 还提到教师、家长、学校管理者、竞赛评委四类辅助角色。

### 成功指标

| 文档 | 指标 |
|------|------|
| V1 | 未定义量化指标，仅列验收清单 |
| V2 | 北极星指标：**计划存活率**（第 3 周仍活跃且完成率 ≥60% 的学习者占比 ≥60%）；另设行为、效果、记忆、重排、AI 质量、体验、安全共 12 项量化指标（均标注"待验证"） |
| project_doc.md | 未定义量化指标 |

### 障碍与解决路径

- **RDS 问题**：README 提到 RDS 曾被 FROZEN 冻结（需代码核验）。cloud-onboarding.md 提供了完整的从零开通清单，包括 AK/SK 创建、VPC/子网/安全组配置、provision_cloud.py 脚本。解决路径是补齐凭证后执行 `--apply`。
- **DCS Redis 问题**：README 提到公网接口返回 `DCS.4005` 错误。V2 §8.3 提出解决方案：**不再纠结公网绑定，改为应用与 DCS 同 VPC 内网直连**。开发调试通过 VPN 或跳板机访问。
- **当前阻塞**（cloud-onboarding.md §8）：本机没有 AK/SK、项目 ID、VPC/子网/安全组与 DCS 规格编码，因此真实实例尚未创建。

### 判断

综合三份文档的矛盾信息，最可能的情况是：**RDS 实例曾创建但因欠费/冻结等原因变得不可达，DCS 实例可能创建过但公网绑定失败**。当前应用实际运行在 SQLite + 内存缓存降级模式。cloud-onboarding.md 是为了解决这一问题而编写的操作手册，但尚未执行。

## 7.6 文档质量评价

1. **诚实度高**：func_effect.md 如实标注降级状态，不伪装云服务接入；V2 多处强调"降级必须如实标注"

### AI 生成痕迹评估

文档整体呈现高度结构化、表格密集、语言统一的特征，符合 AI 辅助生成的典型模式。但这不构成质量问题——内容经过审校，技术细节准确，未发现明显的 AI 幻觉（如编造不存在的 API 或虚构测试结果）。`_plan_doc.txt` 本身就是作为"AI 编程提示词"设计的，AI 生成是其预期属性。
